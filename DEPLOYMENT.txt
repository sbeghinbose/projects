Deployment to GitHub + Render

1. Push this source directory to the GitHub repository. Never upload database.db, .env, node_modules, or logs.
2. Connect the GitHub repository in Render and create a Blueprint from render.yaml.
3. This configuration requires a PAID web service and persistent disk. Review and approve charges in Render before deployment.
4. SESSION_SECRET is generated by Render. DB_PATH points to the persistent disk. The 500 questions import automatically.
5. Before sharing the site, privately transfer the existing database.db to /var/data/database.db to retain the two staff accounts, students, and results. Stop the service while transferring and back up the destination first. Never commit the database to GitHub.
6. Restart and verify staff login, student registration, a topic quiz, and marks review. Use the HTTPS URL returned by Render.
7. Sessions are in memory: a restart logs users out, but the persistent database keeps accounts and quiz results. Run only one service instance with this SQLite configuration.

GitHub Pages serves static pages and cannot run this Node.js/SQLite application.
